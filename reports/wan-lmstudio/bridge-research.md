# Lokale LM-Studio–ComfyUI-Anbindung: Quellenprüfung

Stand: 09.10.2026, etwa 20:57 Uhr Europe/Berlin. Recherche und lokale GET-Abfragen; durch diesen Agenten keine Installation, Konfigurationsänderung oder Renderausführung. Nur dieser Bericht wurde geschrieben.

Empfehlung: vorhandenes **sumitchatterjee13/comfyui-mcp-server** separat installieren und über stdio an LM Studio anschließen. Es passt besonders gut zu längeren Wan-Videos und liefert deren echte lokale Dateipfade. Voraussetzung ist eine zusätzliche API-Exportdatei des derzeitigen UI-Workflows. **Comfy-Org/comfy-mcp** ist die offizielle Alternative, wenn unmittelbare UI-Workflow-Verarbeitung entscheidend ist. Beide sind installationsfähige vorhandene Lösungen; ein neuer eigener Server ist dafür nicht erforderlich. Die Empfehlung beruht auf Quellcodeprüfung, noch nicht auf einem lokalen MCP- oder Rendertest.

## Option 1: gespeicherter API-Workflow, kleine direkte Anbindung

Quelle: [Repository und Installationsanleitung](https://github.com/sumitchatterjee13/comfyui-mcp-server/tree/98b663bdea9097fe8777312d71b393c5b2c1e7a5), geprüfter Commit `98b663bdea9097fe8777312d71b393c5b2c1e7a5`.

- Startpunkt `python server.py --comfyui-url http://127.0.0.1:8188 --comfyui-output-dir D:/MORPH-Studio/output`; MCP über stdio. Lokales ComfyUI wird nur per HTTP angesprochen. Keine Anmeldung für diesen lokalen Betrieb. [Start und HTTP-Kern](https://github.com/sumitchatterjee13/comfyui-mcp-server/blob/98b663bdea9097fe8777312d71b393c5b2c1e7a5/comfy_core.py)
- `comfyui_run_workflow`: Eingaben `workflow_path`, optionale `overrides` als `{"6.text":"...","252.image":"..."}` und `label`; sofortige Rückgabe von `prompt_id`. Änderungen werden auf einer Kopie im Speicher angewandt. API-JSON wird akzeptiert, UI-JSON ausdrücklich abgelehnt. `comfyui_poll_workflow(prompt_id)` liefert Zustand/Fehler; `comfyui_get_outputs(prompt_id, copy_to?, filename?)` liefert `node_id`, `kind`, `path`, `exists`, `bytes`, `mtime`; zusätzlich `comfyui_list_queue` und `comfyui_cancel`. Die MCP-Schemata dieser Eingabewerkzeuge haben einen äußeren `params`-Eintrag, z.B. `{"params":{"workflow_path":"D:/.../Wan-API.json","overrides":{"6.text":"..."}}}`. MP4 unter VHS-Ausgabeschlüssel `gifs` wird ausdrücklich als Video erkannt. [Workflow-Werkzeuge](https://github.com/sumitchatterjee13/comfyui-mcp-server/blob/98b663bdea9097fe8777312d71b393c5b2c1e7a5/workflow_tools.py)
- `comfyui_upload_image`: `params.paths` mit absoluten lokalen Bildpfaden, optional `subfolder`, `overwrite`; zurückgegebenen `load_image_name` anschließend als Bildwert einsetzen. Für Originalschutz `overwrite=false` setzen, da der Paketstandard true ist. `comfyui_list_input_images` zeigt vorhandene Eingaben. [Upload-Werkzeuge](https://github.com/sumitchatterjee13/comfyui-mcp-server/blob/98b663bdea9097fe8777312d71b393c5b2c1e7a5/upload_tools.py)
- README: Python mindestens 3.10; deklarierte Laufzeitabhängigkeiten `mcp>=2,<3`, `pydantic>=2`, `Pillow>=10`; requirements enthält außerdem pytest. Kein Torch in diesen Anforderungen. Python 3.13 fällt in den genannten Bereich; tatsächliche Installation/Imports unter 3.13 sind noch ungeprüft. Node wird nicht benötigt. Separates Python-Umfeld verwenden, keine Pakete in ComfyUIs eingebautem Python ändern. [Anforderungen](https://github.com/sumitchatterjee13/comfyui-mcp-server/blob/98b663bdea9097fe8777312d71b393c5b2c1e7a5/requirements.txt)

Grenze: Datei- und Verzeichniszugriffe sind keine Forge-Sandbox; gezielt nur Workflow-/Upload-/Status-/Ausgabewerkzeuge benutzen. `type=temp` wird als Nachbarverzeichnis `D:/MORPH-Studio/temp` aufgelöst, während diese Installation `D:/MORPH-Studio/temp/comfyui` verwendet. Gespeicherte Wan-Ausgaben haben `save_output=true` und liegen im konfigurierten `output`; temporäre Vorschaupfade sind deshalb gesondert ungeprüft.

## Option 2: offizielles Comfy MCP mit UI-Unterstützung

Quelle: [Comfy-Org/comfy-mcp](https://github.com/Comfy-Org/comfy-mcp/tree/8ade289b7ce05a7769305e10b2aecdb30cbf2658), geprüfter Commit `8ade289b7ce05a7769305e10b2aecdb30cbf2658`, Version 0.10.0.

`comfy-mcp` spricht stdio und benötigt zusätzlich `comfy-cli>=1.14.0`; `COMFY_BIN` kann dessen absoluten Pfad festlegen, `COMFYUI_URL=http://127.0.0.1:8188` das bestehende Backend. ComfyUI neu zu installieren oder seine Torch-Umgebung zu verändern ist für diese Verbindung nicht erforderlich. Der lokale Wan-Graph enthält keine Partner-API-Knoten; dafür ist kein Cloudlogin/API-Key nötig. Partner-/Cloudfunktionen des größeren Pakets gehören nicht zu diesem Auftrag. [README](https://github.com/Comfy-Org/comfy-mcp/blob/8ade289b7ce05a7769305e10b2aecdb30cbf2658/README.md)

Relevante Werkzeuge: `list_workflow_slots(workflow_path)`; `set_workflow_slot(workflow_path, overrides, stdout=true)` mit strukturierten Werten `{"address":"6.text","value":"..."}`; `upload_file(paths, overwrite=false)`; `validate_workflow(workflow_path)`; `run_workflow(workflow_path, wait=false)` akzeptiert API- und UI-JSON; `job(action="status", prompt_id=...)`; `fetch_outputs(prompt_id, out_dir, url_only=false, inline_images=false)`. UI-Anpassung mit stdout=true gibt einen geänderten Graph zurück, schreibt das Original nicht um; für run_workflow benötigt dieser Graph anschließend eine separate Arbeitsdatei. Generische Ausgabe-Dateien werden gesammelt; der konkrete VHS-MP4-Pfad wurde hier nicht getestet. [Werkzeugquellcode](https://github.com/Comfy-Org/comfy-mcp/blob/8ade289b7ce05a7769305e10b2aecdb30cbf2658/src/comfy_mcp/server.py)

Python mindestens 3.10, Anforderungen `mcp>=2,<3`, `pydantic>=2`, `anyio>=4.9`; kein deklarierter Torch-Bedarf des MCP-Pakets. CLI bringt zusätzliche Verwaltungsabhängigkeiten mit. Python-3.13-Kompatibilität ist deklarativ gegeben, tatsächlicher lokaler Import/Handshake ungeprüft; Node nicht benötigt. Auch die Umwandlung der konkreten Custom Nodes/Seed-Frontendlogik bleibt vor dem ersten Render zu prüfen. [Paketmetadaten](https://github.com/Comfy-Org/comfy-mcp/blob/8ade289b7ce05a7769305e10b2aecdb30cbf2658/pyproject.toml)
